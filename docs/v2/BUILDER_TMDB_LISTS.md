## Product contract

**TMDB Lists** is available from selected Folder → Add Source and from the guided New Collection/New Folder launcher. It accepts one public TMDB list per line as either a canonical positive signed-32-bit decimal ID or an exact HTTPS `themoviedb.org/list/<id>` URL with an optional safe slug. Query and fragment text are ignored only after scheme, exact host, credentials, port, raw path, and ID validation. Search is not part of this family.

The first version exposes neither Last Updated metadata nor username/account search. It does not call v4 account-list enumeration or infer dates from response headers, ETags, list IDs, website content, or other indirect evidence.

Resolve is explicit and never rewrites the textarea. Successful lines accumulate as an uncapped ordered removable selection; invalid, inaccessible, malformed, rate-limited, timed-out, and network-failed lines retain per-line feedback beneath the input. Each error identifies its line and complete submitted value, and editing the textarea clears stale errors. **Clear input** clears the textarea and its input-specific errors/notices without removing resolved selections. A repeated already-selected ID is a silent no-op with no network request; repeats within one submitted batch show one calm batch-duplicate notice, including equivalent numeric-ID and canonical-URL forms. Newly resolved lists append in first-seen order, so selected order determines Folder order in hierarchy creation and Source order in selected-Folder Add Source. Successful metadata supplies the exact ID, public name or `TMDB list <id>` fallback, description, item count, creator when reliable, and ordered mixed Movie/TV title rows.

Selected-folder Review exposes the shared collapsed **Source names** disclosure (#257), with one optional final title per selected List, stable List-ID context, automatic blank/reset recovery and unchanged original order. See [the shared Add naming contract](./BUILDER_SOURCE_ADD.md#optional-source-names-in-selected-folder-add-257). Add Source appends the ready LIST Sources directly to the selected Folder; it creates no Folders and exposes no Folder-name or container presentation controls. Its final action remains **Add N sources**.

Guided New Collection/New Folder uses **Select → Names → Appearance**. Select retains resolution, ordered selection, removal and Preview. Its forward action is **Continue to Names**; Names continues to Appearance; Create appears only on Appearance. This is the TMDB Lists hierarchy contract, not a stage change for other families. New Collection creates one Collection with `N` ordered sibling Folders and one LIST Source in each. New Folder creates `N` sibling Folders in the selected Collection. Collection-wide destination duplicates are omitted in New Folder; counts describe only actual ready bundles.

**Names** starts with output counts and prominent selected/omitted/elsewhere summaries, followed by the New Collection name and editable ready Folder cards. Each card retains its external List name, canonical ID, available count and Original order. Folder names default to the resolved external name or `TMDB List <id>` and drafts remain keyed by canonical List ID. Ready cards are neutral; elsewhere-ready cards use compact cyan informational wording with actual occurrence locations behind **Where else?**. An amber **Already in this collection (N) · omitted** disclosure groups compact identity rows. Omitted Lists create nothing and expose neither Folder-name nor Source-name controls.

Optional hierarchy Source names use the existing collapsed **Source names** disclosure for ready output only. Existing list-derived defaults, per-List customisation and blank/reset recovery remain available; no generic “Titles” name is introduced. Duplicate proposed visible Folder names among ready output produce a calm, non-blocking warning using case/spacing/punctuation comparison without stripping articles. The distinct Lists `21608` and `5916`, both named Musicals, remain separate canonical identities and may create two same-name sibling Folders. The warning never renames, merges or blocks them.

The same softer secondary action follows **Back to selection** on Nothing to add. It clears resolved selections and all per-List Folder/Source naming drafts, including earlier removed Source-name overrides, then returns to Select with the textarea unchanged and focused. Placement/advisory output disappears, Continue is disabled, and nothing resolves, applies or changes the project revision. There is no confirmation; explicit re-resolution restores ordinary generated names. Existing Collection-name and shared Appearance choices remain. Add Source does not gain this action.

It has the compact omitted group, Back to selection, Clear lists and Close; no naming controls, Appearance, disabled Create action or content mutation. ## Persisted source contract

Every newly created source has exactly:

```json
{
  "title": "Resolved or edited source name",
  "sortBy": "original",
  "tmdbId": 123,
  "filters": {},
  "provider": "tmdb",
  "mediaType": "MOVIE",
  "tmdbSourceType": "LIST"
}
```

`mediaType: "MOVIE"` is the canonical source-level current Nuvio representation even when the remote List contains Movies and Series; it is not a claim that the remote List is Movie-only. Owner runtime testing in current Nuvio passed Movie-only, Series-only, and mixed Lists with this fixed value: Nuvio derived each returned item's actual Movie/Series type from TMDB `media_type`, routed items accordingly, preserved original order, and retained `MOVIE` plus `original` in an immediate export. Keeping one fixed source identity avoids unstable composition inference for mutable Lists. The source is native and authoritative in `sources`; it is never projected into `catalogSources`.

Selection identity is `tmdb|LIST|<canonical id>`. Physical duplicate identity is `tmdb|LIST|<canonical id>|MOVIE`. Imported numeric and decimal-string IDs normalize only for identity comparison; preserved raw representation remains under the existing importer/serializer contract. Destination-folder duplicates are omitted normally and may be explicitly overridden in Add Source. Elsewhere matches are informational and remain addable. New Folder omits exact identities already anywhere in its destination Collection so it never creates an empty Folder; New Collection treats project matches as informational. Every mutation rebuilds or revalidates current placement and applies one ordinary atomic controller batch.

## Provider and Preview

The injected provider opens with page 1 and requests later pages only through explicit Preview progression:

```text
GET /3/list/{canonical signed-int32 ID}?language=en-US&page={1..5}
```

The frontend normalizer fails closed for mismatched IDs, missing item counts, malformed title rows, and unknown `media_type` values. Movie rows use `title`/`release_date`; TV rows use `name`/`first_air_date`; source order follows the returned `items` array. HTTP 401/403/404 share safe inaccessible/not-found copy. Rate limit, timeout, network, non-JSON, and malformed responses use sanitized retryable errors. Only successful responses—including a successful empty list—enter the bounded 40-entry, five-minute in-memory cache. Concurrent identical requests share one in-flight request while each consumer retains its own stale/abort outcome.

Add and guided creation expose Preview on the resolved-list Choose cards, while Source Edit exposes the shared title Preview action. Lists Review deliberately omits Preview so it can focus on placement, presentation, names, IDs, counts, **Original order**, duplicates, and the final atomic action. Back from Review preserves the resolved selection so Preview remains immediately available on Choose without resolving again. All three Preview entry points reuse the shared body-portalled poster-only dialog. The count/order summary identifies the mixed List without a redundant visible **Titles** line; accessibility labels still use Titles rather than Movies or Series. Opening Preview is explicit and does not mutate, save, re-resolve placement, or change source order.

The current [shared Preview contract (#226)](./BUILDER_TITLE_PREVIEW.md) expands original and recognized List sorts through sequential pages 1–5, stopping at the first 100 ordered source-result positions before poster filtering. Every page is projected independently using the existing List comparator and then appended; there is no global re-sort or claim of globally highest-ranked items. Unknown imported sorts remain page-one-only with the existing neutral fallback. Imported filters remain unapplied.

The shared body scroll owner retains the bounded initial viewport, fixed Close, native lazy images and three-phone/five-desktop columns. Further requests require deliberate near-bottom progress or Load more titles. Failures retain loaded pages and explicit Retry requests only the failed page. Reopening uses unexpired raw pages with an independent sort projection and resets visual scroll to the top. Counts distinguish loaded positions, duplicates and unavailable posters; “All” requires established completion. See the shared contract for conservative total reliability and exact status wording.

## Source Edit

A complete native `LIST`/`MOVIE` source with a string `sortBy` and a filters object is registered through the existing source-editor adapter registry. Populated filters need not be supported or valid Discover criteria because Edit owns only Source name and deliberately changed sorting. List ID remains a safe new-tab link to `https://www.themoviedb.org/list/<id>`. The existing touched-field mechanism applies a minimal patch; opening, Cancel, untouched Save and title-only Save preserve the exact original sort, including whitespace, case and the date alias. Filters, imported unknown fields, IDs, artwork, raw snapshots and source ordering remain untouched. Existing physical List duplicate identity and stale-session guards are unchanged.

The shared **Sort titles by** control offers these Edit-only choices:

| Label | Replacement value |
| --- | --- |
| List order | `original` |
| Recent | `primary_release_date.desc` |
| Top rated | `vote_average.desc` |
| Most voted | `vote_count.desc` |

`first_air_date.desc` is a recognized Recent alias in the inspected List resolvers and is preserved unless replaced deliberately. Unfamiliar values are not inserted into the verified choices and do not select a default or raise a validation error. The editor shows: **This imported list uses ‘xxx’. Choose another sort to change it, or leave it unchanged to keep the original.** Malformed non-string sorts and invalid identity/filter shapes retain the existing preservation-only boundary.

Source cards use these same List sort definitions: **List order**, **Recent**, **Top rated**, **Most voted** and neutral **Imported sort** for unfamiliar strings, including empty/whitespace values. The compact card does not display the unfamiliar raw value. Creation review keeps its existing **Original order** wording and behavior.
